Current work

Running a small studio, still writing the gameplay code

Day to day, I split my time between studio leadership and hands-on engineering on Thalassophobia: gameplay systems in C++, multiplayer architecture, AI behavior, and the technical design decisions that connect them. Development philosophy

How I approach building games

Systems before content

A reusable framework compounds — every project after the first ships faster because of it. I'd rather spend a week on a modular AI framework than hand-script one enemy at a time.

Multiplayer from day one

Retrofitting networking into single-player-first code is where most co-op games go wrong. Replication and authority get designed in from the first prototype, not bolted on later.

C++ for structure, Blueprint for iteration

Core systems live in C++ where performance and structure matter; Blueprint exposes the knobs designers actually need to tune without waiting on a recompile.

Design and engineering are one job

Technical game design isn't a separate discipline from programming — the mechanic and the architecture that supports it get decided together, early, while both are still cheap to change.
